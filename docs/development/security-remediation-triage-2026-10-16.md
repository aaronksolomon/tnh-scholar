## Critical exposure assessment and first implementation slices

### B1 — AnyIO transport dependency (small)

`poetry.lock` contains AnyIO 4.14.0 in the main group. Immediate parents are HTTPX, OpenAI, Starlette, and Streamlit. The critical TLS advisory requires a non-ASCII hostname and a separately redirected/hijacked connection. The maintained provider constructs synchronous `OpenAI` (`src/tnh_scholar/gen_ai_service/providers/openai_client.py:33`); no application calls to `AsyncOpenAI`, `httpx.AsyncClient`, or AnyIO were found in the source search. Consequently, exploit reachability through the maintained provider is not established. Optional web paths and SDK internals still warrant review; installation alone does not prove reachability.

Propose a targeted AnyIO lock update within existing parent constraints, with 4.14.2 as the minimum reported fix for all three open advisories. PyPI confirms that release has non-yanked distributions and the current package Python requirement admits Python 3.12; a clean resolver/install check remains required. Avoid adding a direct dependency solely to move a transitive lock entry. Run provider/CLI focused tests, inspect lock churn, and retain the network-path limitation in the PR description. [PyPI evidence](https://pypi.org/pypi/anyio/json).

### B2 — GitPython repository handling (small/medium)

GitPython is directly pinned at 3.1.50 and is also required by development/GUI parents. Application usage opens/initializes repositories, commits prompt changes, and reads history (`src/tnh_scholar/ai_text_processing/prompts.py:345`). The legacy prompt-sharing app clones a URL entered in its UI (`src/tnh_scholar/pattern_share/app.py:209`). These are meaningful repository trust boundaries. A source search found no application `config_writer()`/`GitConfigParser` calls, so the critical config-rewrite chain is not established in the maintained path. Other repository/config/URL advisories still apply to the dependency and need individual consideration.

Propose moving the root pin and lock together to a compatible patched release; 3.1.62 covers the highest listed fix in this inventory. PyPI confirms that release exists with non-yanked distributions. Do not jump to 3.2 solely because it is newer. Validate prompt catalog/git operations and add focused coverage only for changed trust-boundary behavior. Record clone exposure separately for the unsupported legacy UI. [PyPI evidence](https://pypi.org/pypi/gitpython/json).

### B3 — NLTK resource loading and sentence splitting (medium)

NLTK is pinned at 3.9.4. `sent-split` selects a fixed default `punkt` resource, downloads it when absent, then calls `sent_tokenize()` (`src/tnh_scholar/cli_tools/sent_split/sent_split.py:29`, `src/tnh_scholar/cli_tools/sent_split/sent_split.py:63`). This confirms a resource acquisition boundary; it does not establish exploitation of every flagged loader. Source searches found no application use of TransitionParser, Stanford wrappers, or perceptron model persistence. Existing sentence-split CLI tests mock `split_text` and resource setup (`tests/cli_tools/test_other_clis.py:135`), leaving real tokenizer/resource compatibility untested.

Propose reviewing download provisioning and selecting a compatible patched release, with 3.10.3 as the highest listed fixed version. PyPI confirms published non-yanked 3.10.0 and 3.10.3 distributions. Validate the actual resource name required by the selected release and use controlled local tokenizer fixtures rather than implicit network downloads in tests. Review all downloader/resource advisories, not only the critical ones. [PyPI evidence](https://pypi.org/pypi/nltk/json).

Two advisory records require explicit follow-up:

- [GHSA-8mgp-746c-j5xp](https://github.com/advisories/GHSA-8mgp-746c-j5xp) has no listed patched version. Its described preconditions are enforced path security plus attacker-selected model import/export paths; the affected APIs were not found in application code. Proposed disposition: keep open while confirming non-use and constraining supported resource-loading paths; obtain maintainer review before accepting an exception. Do not invent a fixed version.
- [GHSA-x99w-6fgc-pmfw](https://github.com/advisories/GHSA-x99w-6fgc-pmfw) has structured metadata naming 3.10.3 as fixed, while its narrative describes an unpatched release-candidate bypass and says published 3.9.4 was not the claim target. The global advisory metadata was updated on 2026-09-08 and also identifies 3.10.3 as fixed; the [published 3.10.3 release](https://github.com/nltk/nltk/releases/tag/v3.10.3) documents deserialization and other security hardening. This supports selecting 3.10.3 for evaluation, while a targeted loader/source check remains necessary to reconcile the stale narrative. It is not grounds for dismissing alerts or claiming a tested exploit on 3.9.4.
